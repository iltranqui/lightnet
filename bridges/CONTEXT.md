# bridges: vendored cuda-oxide

Vendored from NVlabs/cuda-oxide (Apache-2.0). It compiles Rust `#[kernel]` functions to PTX through a custom rustc codegen backend. Treat as upstream code: change it only for a concrete Darknet need, and keep the change small.

## Table of Contents

- [Role](#role)
- [Crate groups](#crate-groups)
- [Who uses it](#who-uses-it)
- [Constraints](#constraints)

## Role

Provides the device-side API (`cuda-device`), host launch API (`cuda-host`) and the codegen pipeline that `src/darknet-cuda-oxide` builds on. Nothing outside `src/darknet-cuda-oxide` and `src/darknet-cli` (feature `oxide`) depends on it.

## Crate groups

| Group | Crates |
|---|---|
| Device and host API | `cuda-device`, `cuda-host`, `cuda-macros`, `cuda-target-spec`, `oxide-artifacts`, `cuda-artifact-finalizer` |
| Compiler front end | `rustc-codegen-cuda` (excluded from the workspace), `mir-importer`, `dialect-mir`, `mir-transforms`, `cuda-oxide-codegen` |
| Lowering and dialects | `mir-lower`, `dialect-nvvm`, `dialect-ptx`, `dialect-iket`, `iket-lower`, `nvvm-transforms`, `llvm-export` |
| PTX tooling | `ptx-parse`, `ptx-schedule` |
| Intrinsics | `cuda-intrinsics` (hand-owned, see Constraints) |
| FFI and naming | `libnvvm-sys`, `nvjitlink-sys`, `reserved-oxide-symbols` |
| Driver and testing | `cargo-oxide`, `fuzzer` |

Per-crate details: each crate's own `README.md`.

## Who uses it

`src/darknet-cuda-oxide` (kernels) and the `oxide` feature of `src/darknet-cli`. Build via `./tools/test_oxide.sh`.

## Constraints

- Files under `*/src/generated/`, `dialect-nvvm/src/ops/generated/` and `mir-lower/src/convert/generated_intrinsics/` still carry `@generated by cuda-intrinsics-gen ... DO NOT EDIT` banners. The generator and its `intrinsics/` inputs were removed, so these files are hand-owned now and the banners are stale.
- Upstream sync: compare against NVlabs/cuda-oxide rather than editing in place.
